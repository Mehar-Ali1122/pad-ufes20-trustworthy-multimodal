# Trustworthy multimodal skin-lesion diagnosis on PAD-UFES-20

Code and results for the paper:

> Mehar Ali, Naveed Ikram. *Separating clinical signal from missingness shortcuts in multimodal skin-lesion classification: a leakage-controlled reliability evaluation on PAD-UFES-20.* Manuscript under submission. The full citation will be added after publication.

The notebook compares image-only, metadata-only and four image–metadata fusion models (early concatenation, late fusion, cross-attention and MetaBlock-style gating), each with and without modality dropout, on the public PAD-UFES-20 dataset of smartphone skin-lesion images with patient metadata. The evaluation is patient-grouped, leakage-controlled and focused on reliability:

- **RQ1. Discrimination:** balanced accuracy, macro-F1, macro AUROC, and cancer sensitivity and specificity, with patient-level bootstrap intervals and Holm-adjusted paired tests.
- **RQ2. Robustness:** performance when metadata is missing at test time, randomly or in structured clinical scenarios.
- **RQ3. Reliability:** calibration (ECE, Brier score, temperature scaling) and selective prediction (risk–coverage, AURC).
- **RQ4. Subgroups:** performance by Fitzpatrick skin type, age band and sex.
- **Validity checks:** a missingness audit, a restricted-metadata sensitivity analysis, a leakage experiment (patient-grouped vs image-level splits) and an automated quality-control report.

## How to run

The notebook is designed for Google Colab with a GPU. The reported results were produced on an NVIDIA A100.

1. **Get the data.** Download PAD-UFES-20 from Mendeley Data: <https://doi.org/10.17632/zr7vgbcyr2.1>. Put the downloaded archive (a `.zip` file or an extracted folder) in your Google Drive.
2. **Open the notebook in Colab.** Choose *File → Upload notebook*, or open it directly from GitHub. Choose *Runtime → Change runtime type → GPU*.
3. **Set the data path.** In **Part 2 (Configuration)**, set `DATA_PATH` to the location of the dataset in your Drive. The default is:
   ```python
   DATA_PATH="/content/drive/MyDrive/PAD_UFES20_Trustworthy/Datasets/PAD-UFES-20.zip"
   ```
   All outputs (splits, checkpoints, predictions, tables, figures, QC report) are written under `PROJECT_DIR`, which defaults to `/content/drive/MyDrive/PAD_UFES20_Trustworthy`.
4. **Run all cells** (*Runtime → Run all*). Finished training runs are detected and skipped, so the notebook can be resumed after a disconnection.
5. **Check the QC report** at the end (Part 16). Results should be reported only if every check passes.
6. **Before closing Colab**, run `drive.flush_and_unmount()` so that every file is written to Google Drive.

### Main settings (Part 2)

| Setting | Value used in the paper | Meaning |
|---|---|---|
| `SEED` | 42 | Random seed for splits, training and bootstrap |
| `N_BOOT` | 10000 | Patient-level bootstrap resamples |
| `RUN_RESTRICTED_SENSITIVITY` | True | Retrain models on the six almost always recorded metadata fields |
| `FAST_MODE` | False | Debug mode only; never use it for reported results |

## Reproducibility and leakage control

- Five-fold `StratifiedGroupKFold` grouped by patient; no patient appears in more than one of training, validation and test data.
- All metadata preprocessing (imputation, scaling, encoding) is fitted on training folds only.
- Model selection, temperature scaling and abstention thresholds use validation data only.
- The QC report (Part 16) verifies these properties automatically and recomputes reported table values from the saved predictions.
- The configuration is identified by a hash printed in Part 2. The paper's results correspond to configuration `6bef845303cf`.
